# 着地審査の型（レビュー兼指揮）

役割の本分は**独立 gate → GO 判定 → 指揮拠点（#240 系トラッカー）の保全**。
着地・タグ cut・契約変更は統括/実装担当の専権。自己マージは誰もしない。

## 手順（1 PR あたり）

1. **裁可依頼を読む** → PR メタ確認（head sha・base・mergeable_state・diff --stat）。
   base が現 main か、動いていたら world の並行 PR との衝突面を先に把握。
2. **fetch → detach → `/gate`**（独立フル gate・数値で）。
3. **実体レビュー**——申告はディスクで裏取る:
   - 理論核（安全性議論・等価条件）は該当関数を**読んで**主張と突き合わせる。
     出力順がハッシュ反復に依存しないか・キャッシュの寿命はデータの寿命と揃うか・
     miss 経路が byte-authority で高速路は「結果の再生のみ」か、を見る。
   - 「バグを直した」と言うなら直したコードが在ること、「テストで pin」と言うなら
     そのテストが**発動 assert 付き**で在ることを確認する。
4. **実測裏取り**——PR の数値を鵜呑みにしない:
   - byte-identity / engagement / 方向性は `/interleave` の規律で自分の fixture で再現。
   - 敵対 fixture を自作する（ULP 感受性なら小数値・seam に汚れ・未使用列・空辞書系の
     縁）。**空対空の cmp は何も検証していない**（stdout が空で IDENTICAL が出た事故あり
     ——比較対象が非空であることを先に確認する）。
5. **CI** は `get_check_runs` を 1 回（ポーリング禁止・webhook 待ち）。5/5 と実行時刻が
   対象 head のものであることを見る。
6. **判定**は三値:
   - **GO**: 全条件充足。
   - **条件付き GO**: 条件は「1 コミットで満たせる・検証可能な粒度」で書き、
     可能なら文面例まで与える。re-push は差分確認（`/postverify` の interdiff 手順）
     をしてから着地 GO。**条件対応の re-push が「解消 merge だけで条件本体を忘れる」
     取りこぼしは実例がある**——条件の充足を目視で確認してから通す。
   - **差し戻し**: 何が・どこに・どう欠けているかを列挙し、再提出の受入条件を固定。
7. **投稿は最少**: GO は PR に 1 コメント＋トラッカーに 1 記録。投稿前にリーク走査
   （メール・トークン・セッション URL・ローカルパス・モデル ID）。数値は実測のみ。
8. **事後検証**: 着地報告が来たら `/postverify`。終わったら自 branch へ復帰し、
   検証用 fixture・バイナリは削除。

## 判定の原則（実例で校正済み）

- **正直申告は加点**。fixture 再生成・ツール欠落・投資段（退行）の申告は
  台帳規律の証であり、隠されるより桁違いに良い。
- **実測退行の「投資段」は net win まで未マージ**。「次段で回収見込み」では main に
  入れない。回収段を同 PR に積ませ、wash なら**両段とも破壊**して負の結果を台帳へ
  （固定幅パックキー・mmap 窓の前例）。
- **「作って計測して破壊した記録」は成果**。再訪条件つきで BENCHMARKS に残させる。
- **申告と disk の乖離は、それ自体が差し戻し理由**（CHANGELOG が「移行できる」と
  無条件に謳い、実際は特定形状で明示拒否——のような乖離）。
- **既存欠陥の発見は PR の否ではない**。切り分け（main でも再現するか）を自分で行い、
  退行でなければ「別スライス＋flip/リリースの前提条件として docs に固定」で通す。
- 破壊的変更・契約変更は CHANGELOG＋docs 明記（policy v2「documented」流儀）が条件。
- 迷ったら 8 法則（byte-identity・continue-first・never-silent・IR 可逆・chunk 独立・
  Observable First）に照らす。**性能は正しさの従属変数**——正しさゲートを緩めて
  得た速度は受け取らない。
